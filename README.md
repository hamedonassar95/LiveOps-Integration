# LiveOps Integration — VibePaper

تطبيق مستقل لصنّاع المحتوى لتجربة إنشاء خلفيات هاتف بالذكاء الاصطناعي. يستخدم
واجهة React وVite في المتصفح وخادم Express في الخلفية. يبقى هذا المشروع منفصلًا
عن Devobs؛ التكامل الاختياري مع Devobs مخصص لمراقبة نتائج CI فقط.

## ما هو موجود الآن

- توليد حتى أربع تنويعات للخلفية، مع اختيار نسبة الأبعاد والدقة.
- استخدام صورة مرجعية لإلهام تنويعة جديدة، ومعاينة شاشة القفل وعارض ثلاثي الأبعاد.
- إدخال صوتي لتحويل الوصف إلى نص، ومسار تجريبي لتحريك الخلفية إلى فيديو.
- سجل المتصفح المحلي وإمكانية تنزيل الصور.

هذه القدرات تعتمد على واجهات Google GenAI الموجودة في الخادم، وتوفر النماذج
والحصص الحالية. لم نتحقق هنا من تشغيل استدلال حي أو من إتاحة توليد الفيديو.
بناء المشروع واختبار الجسر لا يستهلكان حصة Gemini.

## التشغيل المحلي

يتطلب Bun `1.4.4` أو إصدارًا متوافقًا مع ملف القفل:

```sh
bun install --frozen-lockfile
cp .env.example .env
bun run dev
```

أضف `GEMINI_API_KEY` إلى `.env` على الخادم المحلي إذا أردت استخدام التوليد أو
النسخ الصوتي. لا تضعه في React أو ملفات `VITE_*` ولا ترفعه إلى Git. واجهة
الموقع قد تعمل من دون المفتاح، لكن طلبات Gemini لن تعمل. استخدم الأوامر التالية
للتحقق:

```sh
python3 -m unittest discover -s tests -v
bun run lint
bun run build
```

لا يوجد ملف `LICENSE` على مستوى المستودع. يحتوي `src/App.tsx` على ترويسة
ترخيص Apache-2.0 خاصة بالملف، لكنها لا تكفي وحدها لتحديد ترخيص بقية المستودع.
تعامل مع إعادة استخدام المشروع كله على أنها غير محددة إلى أن يختار المالك
ترخيصًا عامًا ويضيفه.

## مراقبة CI في Devobs

بعد دمج تغيير استقبال الأحداث في
[Devobs](https://github.com/hamedonassar95/Devobs)، يستطيع CI إرسال نتيجة بناء
`main` إلى مستقبِل Devobs. البيانات المرسلة تقتصر على اسم المستودع والفرع وSHA
ومعرّف التشغيل ومحاولته واسم سير العمل ونتيجته. لا تُرسل صور أو صوت أو مطالبات
أو سجلات التطبيق أو مفتاح Gemini.

للتفعيل، أنشئ يدويًا رمز وصول دقيقًا محدودًا إلى مستودع Devobs وحده بصلاحية
`Contents: write` المطلوبة لواجهة
[repository dispatch](https://docs.github.com/en/rest/repos/repos#create-a-repository-dispatch-event)،
ثم احفظه في إعدادات أسرار GitHub لهذا المستودع باسم
`DEVOBS_DISPATCH_TOKEN`. لا يقرأ هذا التغيير السر أو ينشئه. إذا لم يُضف السر،
يستمر CI ويظهر في ملخص التشغيل أن الإرسال غير مفعّل. لا يستخدم الجسر أسرارًا
في بناءات pull request ولا ينفذ معالجة أو نشرًا تلقائيًا.

مستقبِل Devobs يتحقق من الحقول والمصدر والفرع والنتيجة، ثم يضيف ملخصًا إلى تشغيل
GitHub ويكتب الحدث في مساحة مؤقتة داخل ذلك التشغيل. لا توجد قاعدة بيانات دائمة
لهذا الجسر؛ سجل التشغيل يخضع لمدة الاحتفاظ المضبوطة في GitHub. كما أن بيانات
المرسل ادعاء مرتبطًا بالرمز وليست إثباتًا مشفرًا مستقلًا لتشغيل المصدر.

## سير CI والتبعيات

يستخدم [Bun](https://github.com/oven-sh/bun) (MIT) وملف `bun.lock` المقفول.
إجراء `oven-sh/setup-bun` المستخدم في CI مرخص بـMIT ومثبت على SHA كامل؛ إجراء
`actions/checkout` مثبت كذلك على SHA كامل. لا تُضاف خدمات مستضافة أو عمليات
مجدوَلة أو مكونات خارجية إلى وقت تشغيل التطبيق.
